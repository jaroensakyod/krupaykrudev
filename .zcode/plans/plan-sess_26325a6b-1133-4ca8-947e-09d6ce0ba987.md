# แผนพัฒนา krupay — Thai Teaching Media Marketplace (Sellable MVP v1)

## Tech Stack (ล็อกแล้ว ห้ามเปลี่ยนกลางทาง)
- **Framework:** Next.js 15 (App Router) + TypeScript — Modular Monolith
- **DB:** PostgreSQL (Neon) + **Prisma** ORM + migrations
- **Hosting:** Vercel
- **Storage:** Cloudflare R2 (S3-compatible) — original files private + signed URL, preview ผ่าน CDN
- **Auth:** Email/password + Google (Auth.js), email verification, session/audit
- **AI:** Google Gemini ผ่าน **AI Gateway ตัวเดียวกลาง** (interface `generate()`/`generateStructured()` เปลี่ยน provider ได้) + `ai_jobs` table + cost/quota guard
- **Payment:** Payment Adapter + Mock/Sandbox (webhook idempotent, backend verify เท่านั้น) — รอยืนยัน provider จริงก่อน production
- **UI:** ออกแบบทุกหน้าผ่าน **Stitch (stitch.withgoogle.com)** → export HTML/CSS → แปลงเป็น React component + design system ใน Next.js

## Workflow UX/UI ผ่าน Stitch (ตามที่ user กำหนด)
ก่อนเขียน UI ของแต่ละ phase จะ:
1. ออกแบบหน้าที่เกี่ยวข้องใน Stitch (ภาษาไทย, mobile-first ตาม section 84)
2. Export design จาก Stitch
3. แปลงเป็น component จริง + ต่อ data/API
ชุดแรกที่ต้องออกแบบ: Home, Search, Product Detail, Creator Page, Creator Upload Wizard (9 steps), Cart/Checkout, Creator Dashboard, Admin Moderation

## ลำดับงาน (ตาม PRD Phase 0–13, งานนอก V1 freeze ไป BACKLOG ทั้งหมด)

**Phase 0 — Foundation:** init repo + Next.js/TS, env validation, Prisma+Neon setup, Auth.js (email+Google), RBAC (GUEST/BUYER/CREATOR/MODERATOR/ADMIN), design system base, logging, CI

**Phase 1 — User & Creator:** users schema, Become Creator flow + Creator Terms, creator_profiles, หน้า `/creator/{slug}` สาธารณะ, dashboard shell

**Phase 2 — Catalog:** products + product_versions schema, taxonomy จาก DB (product_types, subjects, grades, topics — แก้ผ่าน Admin ได้ ห้าม hard-code), tags, draft product + editor, status lifecycle (DRAFT→...→PUBLISHED) คุมโดย service

**Phase 3 — Files:** R2 integration, signed upload, validation (MINE/extension/size/malformed), SHA-256 hash, product_files (file_role), preview processing + watermark, signed download + download_events

**Phase 4 — AI:** AI Gateway + Gemini provider, ai_jobs schema + cost logging, 3 tasks: metadata / SEO / quality — structured output + validation, Creator ต้อง confirm/edit เสมอ, AI fail = กรอกมือได้ (ห้าม block publish)

**Phase 5 — Trust:** copyright declaration, duplicate check (SHA-256), moderation_cases, admin moderation queue (approve/reject/needs changes/suspend), reports, strikes, audit_logs

**Phase 6 — Marketplace (UX/UI ผ่าน Stitch):** Home, Product page, Creator page, Search + Thai normalization (`ม.3`=`ม3`=`มัธยม 3`, synonym table), filters/sort, related products (rule-based), SEO metadata + sitemap + structured data, empty search = NOINDEX

**Phase 7 — Commerce:** carts/cart_items (revalidate price ตอน checkout — client price ห้ามเชื่อ), checkout, orders + order_items snapshot (ราคา/fee/version ติดหนาด), Payment Adapter + Mock sandbox + webhook (verify + idempotent), entitlements, purchase history

**Phase 8 — Finance:** immutable ledger_entries (SALE/PLATFORM_FEE/PAYMENT_FEE/CREATOR_EARNING/REFUND/PAYOUT/ADJUSTMENT), commission engine (15% จาก platform_fee_rules แก้ได้), pending→available balance, refund (reverse ledger ห้ามลบ), payout request + admin payout, reconciliation

**Phase 9 — Buyer:** Downloads page (จาก entitlement), reviews (verified purchase only, กันซ้ำต่อ order item), wishlist, account, notifications (in-app + email)

**Phase 10 — Analytics:** event service + session id, search_events (เก็บ raw + normalized, **result_count=0 เก็บเสมอ**), product funnel events (impression→view→preview→cart→checkout→purchase→download), purchase attribution, creator analytics, founder dashboard

**Phase 11 — Admin:** dashboard (GMV/orders/pending queue), user/creator/product management, order/payment/payout inspection, report queue, taxonomy manager, AI usage dashboard

**Phase 12 — Hardening:** authorization audit, rate limiting, upload abuse test, payment idempotency test, ledger test, download security test, AI failure test, mobile QA, SEO QA, performance QA, backup/restore test

**Phase 13 — Launch:** production env, domain, email (Resend), production R2, monitoring (Sentry), legal pages (Terms/Privacy/Copyright), help center, seed marketplace

## กติกาการทำงาน
- ทำตาม task template ของ PRD section 107 (bounded task มี acceptance criteria + tests ทุก task) ไม่สั่งงานกว้าง ๆ
- Critical Path ต้องผ่านก่อน (Creator→Product→Publish→Buyer→Payment→Entitlement→Download→Ledger→Balance) แล้วค่อย P1 (AI SEO, Analytics, Review, Wishlist)
- ทุก protected action ตรวจสิทธิ์ server-side, financial record ห้าม hard delete, webhook/payout idempotent
- MVP เสร็จ = E2E ผ่าน (Creator สมัคร→อัปโหลด→AI ช่วย→approve→ขายได้ / Buyer ค้น→จ่าย→โหลดได้ / เงิน trace ได้) โดยไม่ต้องแก้ DB มือ
